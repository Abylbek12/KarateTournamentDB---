# CLAUDE.md — Apsatarov

Сайт для турниров по каратэ: https://apsatarov.vercel.app (репозиторий `Abylbek12/KarateTournamentDB---`, ветка `main`).
Витрина турниров, регистрация, жеребьёвка и сетки, расписание татами, онлайн-табло, судейство и протоколы,
медконтроль, аналитика, ассистент «Сенсей» (Claude). Языки интерфейса: русский (основной), кыргызский, английский.

## Про владельца (важно для стиля работы)

Владелец сайта — не программист, а предприниматель: проходит курс по созданию сайтов для бизнеса.

- Любое действие, которое трудно откатить (удаление данных, смена базы, платные сервисы, публикация на боевой сайт) — сначала спроси.

## Стек

- Клиент: React 19 + Vite 8 + Tailwind CSS 4, TypeScript. Иконки `lucide-react`, анимации `motion`.
- Сервер: Express 4 (`server.ts`, ~1500 строк), запускается через `tsx`. Хранилище — `server/store.ts`.
- ИИ «Сенсей»: Anthropic SDK, модель из `CLAUDE_MODEL` (по умолчанию `claude-opus-5-5`), маршрут `POST /api/chat`.
- Хостинг: Vercel (регион `fra1`). Node 22.x.

## Команды

```bash
npm install
npm run dev          # http://localhost:3000 (сервер + Vite в одном процессе)
npm run lint         # проверка типов: tsc --noEmit
npm test             # test:draw + test:bouts + test:categories + test:intl
npm run build        # vite build + сборка API в api/_server.mjs
npm start            # боевой режим (после build)
```

Перед коммитом: `npm run lint && npm test`. Оба должны проходить (на 17.11.2026 проходят).
`npm run theme:css` запускается сам перед `dev` и `build`.

## Как устроен проект

```
server.ts            весь API (Express): вход, события, участники, поединки, табло, резервные копии, /api/chat
server/store.ts      хранилище, хеши паролей (scrypt), сессии (cookie), два режима хранения (см. ниже)
api/index.ts         точка входа Vercel: подключает собранный api/_server.mjs (в git не хранится)
vercel.json          сборка, rewrites (/api и /auth → функция, остальное → index.html), редирект со старого домена
scripts/             тесты (test-*.ts) и generate-theme-css.mjs
src/App.tsx          главное приложение, переключение экранов (~2000 строк)
src/components/      экраны и панели (табло, консоль боя, сетки, регистрация, админка, Сенсей и др.)
src/utils/           логика: boutEngine (бой), wkfBracketSeeding (жеребьёвка WKF), bracketProgression,
                     eventCategories, access (права), routes (адреса #...), translations (переводы), serverClock
src/context/         AppContext: тема (светлая/тёмная), язык, крупный шрифт
src/data/            демо-данные и список витринных турниров
src/types/schema.ts  типы данных
public/              статика (favicon, картинки)
```

### Хранение данных
- Ноутбук / свой сервер: файл `DATA_DIR/db.json` (по умолчанию `./data`, в git не попадает).
- Vercel: Postgres (Neon), если задан `DATABASE_URL` или `POSTGRES_URL`. Таблица создаётся при первом открытии.
- Общие данные (участники, поединки, протоколы) синхронизируются через `/api/state/:key` с версиями:
  при одновременной правке второй получает свежую версию и повторяет изменение. Табло на Vercel опрашивает сервер раз в секунду.

### Роли и права
Роли: `admin`, `chief_referee`, `tatami_referee`, `scorekeeper`, `club_coach`, `athlete`, `medical_officer`, гость.
- Таблица «кто какой экран видит» — `TAB_ACCESS` в `src/utils/access.ts`. Это только показ; **настоящую проверку делает сервер**
  (`SHARED_STATE_WRITERS` и проверки роли в `server.ts`). При добавлении экрана или данных правь обе стороны.
- При регистрации можно стать только тренером или спортсменом. Остальные роли выдаёт админ.
- Личные данные спортсменов (многие — дети): дату рождения, вес, лицензию, оплату видят только судьи, секретарь, врач и админ
  (`visibleParticipants` в `server.ts`). Не ослабляй это правило.
- Вход через Google/Facebook не реализован (заглушки).

### Переменные окружения
См. `.env.example`. Главные: `ADMIN_EMAIL` и `ADMIN_PASSWORD` (обязательны в production), `ANTHROPIC_API_KEY`
(без него «Сенсей» скрыт), `CLAUDE_MODEL`, `DATABASE_URL`, `DATA_DIR`, `PORT`.
Файлы `.env*` (кроме `.env.example`) в git не кладём. Секреты никогда не пишем в код, коммиты и чат.

## Правила работы с кодом

- **Тема и цвета.** Файл `src/theme.generated.css` создаётся скриптом `scripts/generate-theme-css.mjs` по классам Tailwind из `src/`.
  Вручную его не правь. Если блок нельзя перекрашивать, добавь ему класс `theme-keep`.
  После изменения цветовых классов проверь и светлую, и тёмную тему.
- **Переводы.** Новые тексты интерфейса добавляй сразу на три языка (ru / ky / en): в `src/utils/translations.ts`
  или через `trLang(language, ru, ky, en)`. Не оставляй текст только на одном языке.
- **Адреса экранов** — через `src/utils/routes.ts` (ссылки вида `#rankings`, `#info;id=...`), чтобы работала кнопка «Назад» и ссылки.
- **Телефоны.** Сайтом пользуются с телефонов и планшетов у татами: проверяй мобильную вёрстку (последний коммит — про это).
- **Жеребьёвка и бои.** Логика в `wkfBracketSeeding.ts`, `boutEngine.ts`, `bracketProgression.ts` покрыта тестами в `scripts/`.
  Меняешь её — запусти `npm test` и при необходимости добавь проверку.
- **Картинки турниров** загружаются только JPEG/WebP (проверка в `server.ts`).
- Сборка API (`api/_server.mjs`) создаётся при `npm run build` и в git не хранится.

## Деплой

Vercel сам обновляет сайт при каждом пуше в `main` на GitHub. Значит, пуш в `main` = публикация на боевой сайт.
Рискованные или большие изменения лучше делать в отдельной ветке и показывать владельцу до слияния
(Vercel делает превью-адрес для каждой ветки). Подробная инструкция запуска и работа без интернета — `DEPLOY_VERCEL.md`.
